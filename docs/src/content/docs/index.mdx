## Why this exists

Most multi-agent starting points are either a thin wrapper around one vendor's SDK, or a
heavyweight framework that owns your control flow. This is neither: the agent loop, harness,
and orchestration are plain, owned code in both runtimes - see [why no orchestration
framework](/architecture/#why-no-orchestration-framework).

## What's in the box

| Layer | Purpose |
|---|---|
| `providers/` | `ChatModel` adapters over Anthropic / OpenAI / Gemini official SDKs + a mock; a resilience decorator adds timeout, retry, fallback |
| `harness/` | The guarantees layer: scoping, idempotency, error classification, budgets, circuit breaker, rate limiting, audit log, boundary guardrail |
| `tools/`, `mcp/` | Typed tool contract with a classified error envelope; MCP client and server |
| `agents/` | Lead agent, subagents, citation agent, and deterministic `needs_review` derivation |
| `a2a/` | Agent-to-Agent server (auth + rate limit) and client |
| `memory/`, `artifacts/` | Plan and artifact stores behind pluggable `PlanStore` / `ArtifactStore` seams |
| `orchestrator/` | Synchronous fan-out/fan-in; depth + retry circuit breakers; session token budget; partial-completion policy |
| `tracing/` | Nested spans (turn → agent → call), OTLP export seam, and a separate 100% audit stream |
| `evals/` | LLM-as-judge rubric + seed set; structural review flags trigger the judge |

Both `typescript/` and `python/` implement every layer, reading shared contracts from `specs/`.
See [Reliability & guarantees](/reliability/) for what the harness enforces around the model.
